## 1. 问题

CodeFlow 平台自己的业务库(seekdb,MySQL 协议,库 `ainative_v2`)里有平台运营的全部事实——需求工单、派发执行、数字员工、澄清会话、交付产物。但**除了写 SQL 之外,没有人能直接从业务语言问出这些数据**。

具体表现为三段断链:

| 编号 | 现象 | 后果 |
|---|---|---|
| **P1** | 想问「最近 7 天每天新增需求多少条」,必须先知道表名(`wi_ticket`)、时间字段(`gmt_create`)、类型过滤(`type='REQ'`)、空间隔离(`workspace_id`) | 业务方问不出,开发方每次都要手写 SQL |
| **P2** | 平台有 106 张表、1013 个字段,且表名是 `wi_`/`rt_`/`ag_` 这类前缀缩写 | schema 对自然语言不友好,LLM 直连全量 schema 会把推理预算耗尽(实测:思考超 16K tokens 仍不产出正文) |
| **P3** | 任何「让 AI 查生产库」的方案,第一反应都是「那它会不会把库改了」 | 缺一套能被验证的只读保证,方案无法落地 |

## 2. 待办

| 编号 | 待办 | 归属问题 | 完成判据 |
|---|---|---|---|
| T-1 | 自然语言问答主循环:提问 → SQL → 只读执行 → 自检重试 → 图表 + 结论 | P1 | `python3 -m chatbi "<问题>"` 一条命令出图出数 |
| T-2 | SQL 生成:实时 schema 上下文 + 表名白名单 + 平台口径规则 | P1 P2 | 生成的 SQL 无需人工修改即可执行 |
| T-3 | SQL 校验器(防线 A):仅单条 SELECT、禁 DML/DDL/多语句/注释注入、表白名单实时读 `information_schema` | P3 | 注入样例 100% 被拦,且不触达数据库 |
| T-4 | 只读账号(防线 B):`chatbi_ro` 只授 `GRANT SELECT` | P3 | 直连执行 `UPDATE` 被 MySQL 拒(`1142`) |
| T-5 | 图表渲染:单文件 HTML,内联 ECharts,离线可看 | P1 | 断网双击能看,零外部请求 |
| T-6 | 自检重试:SQL 跑通但结果不对也要能拦下并重来 | P1 | 「漏 GROUP BY 导致结果被折叠成一行」能被自检发现并重写 |
| T-7 | 单测(≥5 个,含注入样例)+ 3 个演示问答真实出图 | P1 P3 | pytest 全绿;3 张真实图表落盘 |

## 3. 价值

| 维度 | 立项前 | 立项后 |
|---|---|---|
| 业务方取数 | 找开发写 SQL,一轮往返 | 一句话,直接出图出结论 |
| 取数口径 | 每人口头约定,同名不同义 | 口径写进提示词与文档,结论强制带样本量 |
| 数据安全 | 依赖「人别乱写 SQL」 | 应用层校验 + 数据库层权限,两层各自独立可验 |
| 交付物 | 散落在聊天记录 | 结论 + 图表 + SQL 一起归档 |
| 边际成本 | 每问一次都要写 SQL | 同一套口径可复用于下一个问题 |

## 4. 范围界定

### 做

- 自然语言 → SQL → 只读执行 → 自检重试 → 图表 + 结论的完整闭环
- 自研 MySQL wire protocol 客户端(纯标准库,`mysql_native_password`)
- SQL 校验器 + 只读账号两层只读防线
- 单文件离线 HTML 图表(内联 ECharts)
- 平台业务口径固化(需求/已完成/成功率/交付耗时)
- ≥5 个单测(含注入攻击样例)+ 3 个演示问答端到端记录

### 不做

- 不做 BI 语义层/指标库、不建视图或物化表
- 不做多轮对话记忆(每次调用是独立的一次问答)
- 不做鉴权与多用户(面向开发与演示的本地只读工具)
- 不做任何写操作——包括建表、临时表、`INTO OUTFILE`
- 不改平台前后端任何代码;本次改动只落在 `chatbi/` 与 `deliverables/chatbi/`
- 不同步进对外基线仓 `CodeFlow`(独立的发布动作)

## 6. 关键约束

- **零第三方运行时依赖**(仓库规范 `docs/00-开发规范与流程.md` §4),需求方明确不许豁免
- **只读**,平台库任何写操作都必须被拒
- **不硬编码密钥**,端点与口令走环境变量 / `.env`,日志脱敏
- **离线可看**,图表必须是真单文件
- 提交时**只带 `chatbi/` 与 `deliverables/chatbi/`**,不带入同工作区的其他未提交改动
