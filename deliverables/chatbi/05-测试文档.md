## 1. 测试分层

| 层 | 范围 | 依赖 | 运行方式 |
|---|---|---|---|
| **L0 单测** | 纯函数与逻辑:SQL 校验、协议编解码、配置读取与脱敏、图表选型与转义、主循环行为 | 无外部依赖,全部打桩 | `python3 -m pytest chatbi/tests/ -v` |
| **L1 协议层** | MySQL wire protocol 的编解码与握手解析 | 无外部依赖(假 socket) | 同 L0 |
| **L2 集成** | 对真实 seekdb 执行的只读路径与权限边界 | 真实库 + `chatbi_ro` 账号 | `python3 -m pytest chatbi/tests/test_integration.py -v`(需 `.env`) |
| **L3 端到端** | 三个演示问题走完「提问 → SQL → 校验 → 执行 → 自检 → 出图 → 结论」 | 真实库 + 真实 LLM 端点 | `python3 -m chatbi "<问题>"` |

**设计原则**:注入攻击样例**直喂校验器**,不经过 LLM——保证可重复、可回归(LLM 生成是不可控的,用它做安全断言没有意义)。

## 2. L0 / L1 用例

### 2.1 SQL 校验器(`test_sql_guard.py`)

| 编号 | 用例 | 期望 |
|---|---|---|
| SG-01 | 8 条合法只读 SQL(含 JOIN / CTE / 递归 CTE / 子查询 / 聚合分组 / 带分号结尾) | 全部放行 |
| SG-02 | `WITH daily AS (...) SELECT * FROM daily` | CTE 名不被当成表名拦下 |
| SG-03 | **30 条注入攻击样例**(见下表) | 全部被拦 |
| SG-04 | 每条被拒 SQL 的 `reason` | 非空、长度 > 8、可回灌给模型 |
| SG-05 | 空 SQL / 纯空白 | 拒绝 |
| SG-06 | 含空字节 `\x00` 的 SQL | 拒绝 |
| SG-07 | 从 LLM 输出抽取 SQL(有/无代码块围栏/空) | 抽取正确或抛 `SQLRejected` |

**SG-03 注入样例全集**(分组):

| 组 | 样例 |
|---|---|
| 写操作 | `UPDATE` / `DELETE` / `INSERT` / `DROP` / `TRUNCATE` / `ALTER` / `REPLACE INTO` / `CREATE TABLE` / `GRANT ALL` |
| 多语句 | `SELECT 1; DROP TABLE …` / `SELECT 1;UPDATE …` / `SELECT 1 ; SELECT 2` |
| 注释注入 | `--` 行注释 / `#` 行注释 / `/* */` 块注释 / `/*! … */` |
| 越权表 | 白名单外表 / 跨库(`mysql.` / `otherdb.`)/ `information_schema.` |
| 危险函数与文件 | `LOAD_FILE` / `SLEEP` / `BENCHMARK` / `INTO OUTFILE` / `INTO DUMPFILE` / `@@version` / `@secret` / 子查询里藏 `SLEEP` |
| 非 SELECT 开头 | `SHOW TABLES` / `EXPLAIN` / `DESCRIBE` |
| 长度超限 | 9000 字符的 SQL |

### 2.5 主循环(`test_agent.py`)

| 编号 | 用例 | 期望 |
|---|---|---|
| AG-01 | 正常路径 | 出图落盘、结论来自自检、`attempts == 1` |
| AG-02 | 选表收敛 schema | 选表提示词与生成提示词不同;生成提示词只含选中表 |

| AG-04 | 含注释的 SQL | **不产生任何业务查询**(被拦在发往 DB 之前) |
| AG-05 | SQL 被校验器拒绝 | 带中文拒绝原因回灌重写 |
| AG-06 | SQL 执行报错 | 带数据库错误回灌重写 |
| AG-07 | 一直失败 | 重试上限 3 次后抛错,错误信息含「3 次」 |
| AG-08 | 自检判定结果不对 | 带问题描述回灌重写,`self_check_history` 留痕 |
| AG-09 | 查询 0 行 | **只调 1 次生成**(0 行不重试),结论为「无数据」 |
| AG-10 | 自检输出不是合法 JSON | 降级到独立结论生成,整轮不崩 |
| AG-11 | 选表调用失败 | 退回核心表,继续完成问答 |

## 3. L2 集成用例(真实库)

前置:`chatbi/.env` 配好只读账号口令;`platform-seekdb-1` 在跑。

| 编号 | 用例 | 期望 |
|---|---|---|
| IN-01 | `chatbi_ro` 执行 SELECT | 成功返回真实数据 |
| IN-02 | `chatbi_ro` 执行 `UPDATE` | MySQL 拒绝(`1142 UPDATE command denied`),**数据未变** |
| IN-03 | `chatbi_ro` 执行 `DELETE` | MySQL 拒绝(`1142`) |
| IN-04 | `chatbi_ro` 执行 `DROP` | MySQL 拒绝(`1142`) |

| IN-06 | 同一 SQL 分别经自研客户端与 `mysql` CLI | 行数与首行内容一致 |

## 6. 已知测试边界

| 边界 | 说明 | 应对 |
|---|---|---|
| **LLM 不确定** | 生成的具体 SQL 每次可能不同,断言不能写死 SQL 文本 | L0 只断言**行为**(是否被拦、是否重试、回灌内容),不断言 SQL 字符串 |
| **LLM 扩展思考** | 端点模型会先输出 thinking 块,`max_tokens` 过小会没有正文 | 测试用假 LLM;真实验证走 L3,且预算给足(32768) |
| **选表阶段有随机性** | 选中的表可能与预期不同 | L0 只断言「生成提示词不含全量 schema」;真值靠 L3 的结果正确性验证 |
| **数据量极小** | `rt_run` 6 条、`wi_ticket` 11 条、已完成需求仅 1 个 | L3 断言「结构与口径正确」,不断言具体数值;数值在 `demo-session.md` 里如实记录 |
| **时间相关** | 「最近 7 天」随运行日期变化 | 用相对断言(行数 = 7),不用绝对日期 |
| **依赖真实端点** | L3 需要本地代理在跑且模型可用 | 代理不可用时 L3 判为「环境不具备」而非「功能失败」,L0/L1/L2 仍须全绿 |
| **OceanBase 方言** | seekdb 兼容 MySQL 5.7,但支持递归 CTE 与窗口函数(与 5.7 不同) | 集成用例在真实 seekdb 上跑,不假设 5.7 语法边界 |
| **未覆盖** | TLS 连接、预处理语句、多结果集、连接池、并发 | 明确**不支持**(见 `04` §2.2),不测 |
