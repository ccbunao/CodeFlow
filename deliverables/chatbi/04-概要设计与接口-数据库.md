## 1. 概要设计

| 概要项 | 内容 |
|---|---|
| 形态 | 命令行工具(可导入包),无服务端、无 Web 界面 |
| 入口 | `python3 -m chatbi "<问题>"`(必须在仓库根运行,`chatbi` 才是可导入包) |
| 数据源 | 平台业务库 seekdb(MySQL 协议),库 `ainative_v2`,宿主 `127.0.0.1:33060` |
| LLM | Anthropic 兼容端点,`POST {base}/v1/messages` |
| 产物 | `deliverables/chatbi/charts/*.html`(单文件离线图表) |
| 运行时依赖 | 无(纯 Python 3.11+ 标准库) |
| 并发 | 单进程单问答;无并发设计 |

### 处理流程概要

```
question
  ├─(1) 选表:紧凑表清单 → LLM → ≤6 张表
  ├─(2) 生成:选中表字段 + 口径规则 → LLM → SQL
  ├─(3) 校验:sql_guard.check(SQL) → 通过 / SQLRejected(reason)
  ├─(4) 执行:mysql_client.query(SQL) → QueryResult
  ├─(5) 自检:LLM 复核 {ok, problem, conclusion}
  └─(6) 出图:choose_chart → render_chart → 单文件 HTML
```

## 2. 接口契约

### 2.1 LLM 端点(Anthropic 兼容)

**请求**

| 字段 | 类型 | 取值 | 说明 |
|---|---|---|---|
| `model` | string | 取自配置(`ANTHROPIC_MODEL` 默认 `claude-sonnet-4-5`) | 与上游字段名逐字对齐 |
| `max_tokens` | int | 默认 32768 | 该端点模型会输出扩展思考,预算过小会被截断 |
| `system` | string | 角色 + 铁律 + 口径规则 + 表结构 | |
| `messages[]` | array | `[{role: "user", content: "<问题>"}]` | 失败重试时在 content 后追加修正线索 |

**请求头**

| 头 | 值 |
|---|---|
| `Content-Type` | `application/json` |
| `x-api-key` | `<token>` |
| `Authorization` | `Bearer <token>`(兼容部分代理) |
| `anthropic-version` | `2023-06-01` |

**响应(只取用到的字段)**

| 字段 | 用途 |
|---|---|
| `content[].type == "text"` 的 `.text` | 正文;`type == "thinking"` 的块被忽略 |
| `stop_reason` | `max_tokens` 时给出「调大 max_tokens」的明确指引 |
| `error.message` | 异常信息,经 `redact()` 脱敏后回显 |

> **未知字段忽略**:响应里出现本端不认识的字段一律不报错(向前兼容)。

**实测偏差**:配置里写 `claude-sonnet-4-5`,但本地代理实际路由到 `MiniMax-M3.1-Flash` 并输出扩展思考块。本端按 Anthropic 响应结构解析,兼容。

### 2.2 数据库读取接口(MySQL)

**握手(HandshakeResponse41)**

| 字段 | 值 | 说明 |
|---|---|---|
| `client_flags` | `0x1 \| 0x4 \| 0x8 \| 0x200 \| 0x2000 \| 0x8000 \| 0x80000` | 长口令 / 长标志 / 指定库 / 协议 4.1 / 事务 / 安全连接 / 插件鉴权 |
| `max_packet_size` | `0x01000000` | 16MB |
| `charset` | `45` | `utf8mb4_general_ci` |
| `username` | NUL 结尾 | |
| `auth_response` | 1 字节长度 + 20 字节摘要 | `mysql_native_password` |
| `database` | NUL 结尾 | `ainative_v2` |
| `auth_plugin_name` | NUL 结尾 | `mysql_native_password` |

**鉴权摘要**(与上游算法逐字对齐)

```
stage1 = SHA1(password)
stage2 = SHA1(stage1)
token  = SHA1(scramble ‖ stage2) XOR stage1     # 20 字节
```

`ob_native_password`(OceanBase 同算法别名)走同一条路径。

**查询**

| 项 | 内容 |
|---|---|
| 命令 | `COM_QUERY`(0x03) |
| 结果集 | 列数 → N 个列定义 → EOF → 行 → EOF |
| 列定义解析 | catalog / schema / table / org_table / name / org_name(均为 lenenc str)→ 固定字段长度(lenenc int)→ charset(2)→ 列长(4)→ 类型(1) |
| 行解析 | 每字段 lenenc 字符串;`0xFB` 表示 `NULL` |
| 错误 | `0xFF` 包:错误码(2)+ SQL state(5)+ 消息 |

**未启用能力**:`CLIENT_DEPRECATE_EOF`(按经典 EOF 处理)、TLS、预处理语句、多结果集、`COM_QUIT` 之外的连接管理。

### 2.3 元数据接口

| 用途 | SQL |
|---|---|
| 表白名单(防线 A) | `SELECT table_name FROM information_schema.tables WHERE table_schema = 'ainative_v2' AND table_type = 'BASE TABLE'` |
| 表结构 | `SELECT table_name, column_name, data_type FROM information_schema.columns WHERE table_schema = 'ainative_v2' ORDER BY table_name, ordinal_position` |
| DONE 状态名 | `SELECT DISTINCT name FROM wi_flow_state WHERE category = 'DONE' AND workspace_id = 2` |

白名单**每次会话实时读**,不写死表名清单(需求原文明确要求)。

### 2.4 CLI 契约

```
python3 -m chatbi "<问题>" [--workspace N] [--out DIR] [--json] [--sql-only]
```

| 项 | 约定 |
|---|---|
| 退出码 | 0 成功 / 2 配置错误 / 3 数据库连接失败 / 4 查询失败 |
| 标准输出 | `问题:` / `SQL:` / `行数:` / `图表形态:` / `图表文件:` / `尝试次数:` / `结论:` / `数据说明:` |
| 错误输出 | 全部经 `redact()` 脱敏后写 stderr |

## 3. 数据库

### 3.1 外部依赖表(只读声明)

ChatBI **只读**以下外部表,全部位于 `ainative_v2`,全部通过只读账号访问。

| 表 | 用途 | 读取方式 |
|---|---|---|
| `wi_ticket` | 需求工单(需求定义、创建时间、空间、状态) | 直接 SELECT |
| `wi_journal` | 工单流转日志(完成时刻的来源) | 直接 SELECT |
| `wi_flow_state` | 流程状态定义(DONE 状态名) | 直接 SELECT |
| `ag_agent` | 数字员工定义 | 直接 SELECT |
| `rt_run` | 派发执行记录(任务数、状态) | 直接 SELECT |
| `information_schema.tables` | 表白名单 | 元数据只读 |
| `information_schema.columns` | 表结构 | 元数据只读 |

**只读声明**:

1. ChatBI **不执行**任何 `INSERT` / `UPDATE` / `DELETE` / `DDL` / `GRANT`,代码与提示词均不含此类语句,且由校验器强制拒绝。
2. 连接使用专用只读账号 `chatbi_ro`,数据库侧仅授予 `GRANT SELECT ON ainative_v2.*`。
3. ChatBI **不建表、不建临时表、不建视图、不写文件到数据库**(`INTO OUTFILE` / `INTO DUMPFILE` 被校验器拒绝)。
4. ChatBI **不修改平台自身任何代码与数据**,只读取。

### 3.2 本地库 DDL 与恢复语义

**ChatBI 没有本地数据库。** 它是纯命令行工具:状态在内存里,产物是 HTML 文件,没有需要建表、迁移、备份或恢复的持久化数据。

| 维度 | 结论 |
|---|---|
| 本地库 | 无。不引入 SQLite/任何本地存储 |
| DDL | 不适用 |
| 迁移 | 不适用 |
| 恢复语义 | 不适用 |
| 需要落盘的东西 | 只有两类:① 图表 HTML(`deliverables/chatbi/charts/`);② `chatbi/.env`(只读账号口令) |
| `.env` 的恢复 | 重新生成随机口令并重建 `chatbi_ro` 账号即可;口令本身不入库,丢失不影响任何数据 |

因此本项目**不产生本地库 DDL**,这一节如实记录「无」,而不是留空或虚构一份 DDL。

### 3.3 平台侧只读账号的创建

```sql
CREATE USER 'chatbi_ro'@'%' IDENTIFIED WITH mysql_native_password BY '<随机口令>';
GRANT SELECT ON ainative_v2.* TO 'chatbi_ro'@'%';
```

实测 `SHOW GRANTS` 结果:

```
GRANT USAGE ON *.* TO 'chatbi_ro'@'%'
GRANT SELECT ON `ainative_v2`.* TO 'chatbi_ro'@'%'
```

口令由 `secrets.token_urlsafe(24)` 生成,写入 `chatbi/.env`(权限 600,`.gitignore` 拦截),不入库、不进文档、不进日志。
